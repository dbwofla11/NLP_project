## 문제

기존 도구는 회의 내용을 기록하지만, 참여자가 함께 생각을 구성하는 과정까지는 지원하지 않는다는 문제의식에서 출발한다. 한국어 제품·UX 팀이 회의 후 24시간 안에 발화와 아이디어 카드의 근거를 다시 정리하는 상황을 우선 가설로 둔다.

## 제안 솔루션

음성 발화를 아이디어 카드로 만들고, 비슷한 카드를 묶어 관계를 연결한다. 여러 사용자가 하나의 캔버스에서 카드를 이동·강조하며 생각을 표현하고, 회의 후에는 관계와 결정 사항을 정리한다. AI가 결론을 대신 내리기보다 사용자가 구조를 직접 수정하는 방식을 지향한다.

## 검증 과제

4~10명 규모 한국어 제품·UX 팀 10~15곳에서 발화-카드 근거 재탐색의 반복성과 손실을 관찰한다. FigJam·Miro와의 중복, 개인정보, 정확도를 검증한다.

## 종합 기획

### 대상 사용자
- 4~10명 규모 한국어 제품팀·UX 리서치팀

### 문제 정의와 현재 근거
회의 후 ‘누가 어떤 근거로 무엇을 결정했는지’를 복원하면서 원 발화와 카드 관계를 다시 찾고 결정·반론·미결 과제를 정리하는 데 시간이 걸릴 수 있다.

### 최종 범위와 해결안
범용 화이트보드가 아닌 기존 회의/캔버스에 붙는 한국어 승인형 결정 로그. 동의된 음성 전사, 카드, 관계 후보, 원 발화 시각을 연결하고 사람이 수정·승인한다. 제스처·위치 센서·카메라 수집은 제외한다.

### 기존 해결 방식과 경쟁
- FigJam AI·Miro AI의 카드 정렬·요약·클러스터링
- Teams Facilitator의 메모·결정 정리
- 수동 회의록

### 시장·문제 검증 계획
1. 10~15개 팀 관찰·인터뷰와 5팀 파일럿. 결정 근거 찾기 시간 20% 이상 감소, 관계 후보 유용성 5점 중 3.5 이상, 팀당 주 1회 이상 재사용을 본다.
2. 기존 도구와 동일 과업을 비교하고 누락 결정 수와 수정 부담도 기록한다.

### 위험과 중단 조건
- 기존 도구 기능 중복·전환 비용이 커서 차별성은 발화→카드→관계→결정의 근거 추적이다.
- 고객이 동의한 녹음만 사용하고 보관·삭제·권한 및 외부 모델 처리를 명시한다.
- 초안에는 원문·확신도를 연결하고 인간 승인 없이 결정을 확정하지 않는다.
- 5팀 중 3팀 이상이 기존 도구로 충분하다고 하거나 개선이 없으면 중단한다.

### 남은 결정
- 결정 근거 찾기 시간과 누락 결정 수 중 주 지표를 고정한다.
- 한국어 다화자 전사·관계 추론에 필요한 평가 데이터를 확보할 수 있는가?

## 1. 사업 개요
**가칭: TraceBoard** — 원격 워크숍·사용자 리서치에서 발화, 카드, 연결선을 하나의 수정 가능한 ‘논의 지도’로 남기는 협업 보조 서비스다. AI가 결론을 대신 내리지 않고, 각 노드가 어떤 발화·카드에서 왔는지 추적 가능하게 하며 참여자가 즉시 수정·승인한다.
> 
	**범위 선언:** 범용 화이트보드·회의록 제품을 만들지 않는다. MVP는 한국어 원격 워크숍의 음성 전사, 아이디어 카드, 근거 연결, 결정/미결 항목 검수에 한정한다. 제스처·위치 추적·생체정보 처리는 MVP에서 제외한다.

## 2. 문제와 고객
- **초기 고객 가설:** 4~10명 규모의 한국어 제품팀·UX 리서치팀이 회의 후 ‘누가 어떤 근거로 무엇을 결정했는지’를 복원하는 데 시간을 쓴다.
- **문제:** 전사와 요약은 선형적이고, 화이트보드는 수동 정리가 필요하다. 이미 존재하는 카드·결정·반론의 관계와 출처를 다시 찾아야 한다.
- **검증할 고객 과업:** 워크숍 직후 결정 근거, 반대 의견, 담당자, 미결 질문을 10분 안에 확인하고 수정한다.
- 문제 가설은 MeetMap의 시각적 dialogue map 연구로 보강되지만, 구매 의사나 일반화된 생산성 향상은 아직 증명되지 않았다. [MeetMap](https://arxiv.org/abs/2502.01564)
## 3. 솔루션과 MVP
1. 참여자 동의를 받은 회의 음성을 전사하고 발화 시각·화자를 저장한다.
2. 참가자가 만든/음성으로 생성한 카드에 발화 구간을 연결한다.
3. 임베딩 기반으로 **후보 관계**(중복, 근거, 반론, 결정)를 제안한다.
4. 참가자가 후보 관계와 요약을 승인·수정·삭제한다.
5. 회의 후 ‘결정·근거·미결·담당자’ 보드와 근거 링크를 내보낸다.
**비기능 요건:** 프로젝트별 접근권한, 녹음 동의 표시, 원본 오디오 보관기간 설정, 삭제 요청, 생성문구가 초안임을 표시한다.
## 4. 경쟁 및 차별화
- FigJam AI는 스티키 정렬·요약을 제공하고, Miro AI도 키워드·감정 기반 클러스터링을 제공한다.
- Teams Facilitator는 실시간 메모, 결정·미결 요약, 공동 편집을 제공한다.
- 따라서 ‘AI 요약/카드 클러스터링’은 차별점이 아니다.
- **검증할 차별 가설:** 한국어 회의의 **발화→카드→관계→결정** 근거 추적과 사람이 수정한 변경 이력을 한 화면에서 제공하면, 기존 도구보다 회의 후 재확인 시간이 줄어든다.
## 5. 수익·진입 전략
- **모델 가설:** 워크스페이스 단위 B2B 구독. 가격은 지불 의사 확인 전에는 정하지 않는다.
- **초기 진입:** 대학 팀·UX 리서치 스터디 5팀에 4주 파일럿을 제공하고, 이후 소규모 제품팀으로 확장한다.
- **대체 경로:** 기존 Zoom/Teams/FigJam 결과물을 가져오는 읽기 전용 import부터 검증한다. 플랫폼의 비공식 수집·자동 게시 기능은 만들지 않는다.
## 6. 핵심 지표와 검증 설계
- 파일럿 성공 기준: 회의 후 결정 근거를 찾는 시간 20% 이상 감소, 관계 제안의 승인/수정 후 유용성 평가 5점 만점 3.5 이상, 팀당 주 1회 이상 재사용.
- 비교: 기존 FigJam/회의록 방식과 동일 과업을 수행한 시간·누락된 결정 수·참여자 설문을 비교한다.
- 중단 기준: 5팀 중 3팀 이상이 ‘기존 도구로 충분’이라고 응답하거나, 관계 제안의 승인율이 낮고 수정 부담이 더 크면 피벗한다.
## 7. 기술·운영 계획
- 전사(STT) → 화자/시각 메타데이터 → 카드 추출 → 임베딩 검색 → 관계 후보 분류 → 사용자 검수·그래프 저장.
- 한국어 대화체·중첩 발화·전문용어를 별도 평가한다. 관계 생성은 검색된 원문 구간을 근거로만 수행한다.
- 1단계(4주): 업로드 오디오+수동 카드+관계 후보. 2단계(4주): 실시간 동기화/권한. 3단계: 기존 도구 import.
- 수집 데이터의 보관·처리 근거와 조직별 보안 요구는 파일럿 전에 검토한다.
## 8. 주요 위험과 대응
- **경쟁 중복:** FigJam·Miro·Teams의 기능 확대. → 근거 추적과 워크플로 시간을 실험으로 비교.
- **전사/요약 오류:** 잘못된 결정 기록. → 초안 표시, 원 발화 링크, 인간 승인 없이는 확정 상태 금지.
- **개인정보·동의:** 회의 녹음과 발화자 데이터. → 명시 동의, 보존·삭제 정책, 최소 수집.
- **복잡한 UI:** 시각화가 인지 부담을 키울 수 있음. → 기본 화면은 결정/미결 2개 보기, 관계도는 선택 표시.

## 9. 독립 비판 검증 및 피벗 결정
**검증 결론: PIVOT — 범용 협업 캔버스 SaaS는 진행하지 않는다.** 독립 검토에서 FigJam·Miro·Teams가 이미 스티키 정렬, 요약, AI 클러스터링, 공동 메모·결정 정리를 제공함이 확인됐다. 따라서 ‘기존 도구는 기록만 한다’는 주장은 철회한다.
### 반영한 사업 수정
- 제품은 새 화이트보드가 아닌 **기존 회의/캔버스에 붙는 한국어 승인형 결정 로그**로 재정의한다.
- ‘멀티모달’은 제스처/위치 센서가 아니라 **동의받은 음성, 카드, 카드 위치, 원문 시각**의 결합으로 정의한다. 카메라·물리 위치 수집은 제외한다.
- 자동 요약·관계는 추천일 뿐이며, 원문 시각·발화자·수정 이력·명시 승인 없이는 결정으로 확정하지 않는다.
### 검증 게이트
- 10~15개 목표팀의 관찰 및 유료 의향 인터뷰: 구매자, 현재 대체 비용, 보안 요구를 기록한다.
- 기존 도구 대비 한 과업(결정 근거 찾기 시간 또는 누락 결정 수)을 사전 등록해 측정한다.
- 고객 소유·동의된 녹음만으로 PoC를 진행하고, 전사/관계 추천에는 근거와 확신도를 표시한다.
- 5팀 파일럿에서 기존 도구 대비 개선이 없거나 3팀 이상이 전환 이유가 없다고 답하면 중단한다.
### 비판적 리스크
- Miro·FigJam의 기능 중복과 전환 비용.
- 한국어 다화자 전사·화자 귀속·관계 추론의 평가 데이터와 성능 목표 부재.
- 음성·이름·보드 내용이 개인정보가 될 수 있으므로 최소수집, 목적·보유기간 고지, 권한·삭제, 외부 LLM 처리 계약을 선행해야 함.
- 잘못된 결정 귀속이 회의 기록 신뢰를 훼손할 수 있음.

## 검증 목적
이 문서는 **문제 상황이 구체적인지**와 **같은 문제가 반복되는지**만 시장·사용 맥락 근거로 검증한다. 제품 기능의 우수성이나 경쟁 우위는 판단하지 않는다.
## 결론
**판정: 부분 충족.** 회의 후 논의 구조와 결정 근거를 다시 찾는 상황은 반복될 가능성이 있으나, 현재 문제 문장은 대상 고객·발생 조건·손실·현재 대안이 빠져 있어 구매 문제로는 아직 구체적이지 않다.
## 1. 문제 상황의 구체성 검증
현재 문장인 ‘여러 사람이 말로 소통하면 생각을 동시에 표현·정리하기 어렵다’는 현상 설명이다. 다음 5개가 비어 있다.
- **누가:** 제품팀, UX 리서치팀, 학생 팀 중 어느 고객인지 미정.
- **언제:** 회의 중인지, 종료 직후인지, 다음 회의 전인지 미정.
- **반복 단위:** 주간 워크숍/프로젝트/회의당 발생 횟수 미정.
- **손실:** 재정리 시간, 결정 누락, 담당자 혼선의 측정값이 없음.
- **현재 대안:** FigJam·Miro·Teams·수동 회의록 중 무엇이 어느 지점에서 부족한지 비교가 없음.
### 검증 가능한 문제 문장(가설)
> 4~10명 한국어 제품/UX 팀이 원격 워크숍 후 24시간 안에 결정·반론·미결 과제를 정리할 때, 원 발화와 카드 사이의 근거를 다시 찾는 데 시간이 들고 결정 누락이 발생한다.
이 문장은 아직 **사실이 아니라 인터뷰·관찰로 검증해야 할 가설**이다.
## 2. 반복 발생성의 시장 근거
- Microsoft의 2025 Work Trend Index 후속 조사는 31개 시장의 지식노동자 31,000명을 조사하고, 대규모 익명 Microsoft 365 신호를 사용해 업무일의 커뮤니케이션·회의 부담을 분석한다. 이는 회의·후속 협업이 일회성 활동이 아니라 반복되는 업무 맥락임을 뒷받침한다.
- FigJam과 Miro가 스티키 정리·요약·군집 기능을 계속 제공하는 것은 팀이 반복적으로 아이디어를 정리하는 과업을 수행한다는 **시장 신호**다.
- 그러나 이 자료들은 ‘한국어 팀이 발화↔카드 근거를 잃어버린다’거나 그 때문에 새 도구에 비용을 지불한다는 증거는 아니다. 기존 도구로 해결되는 비율도 확인되지 않았다.
**반복성 판정: 업무 맥락은 뒷받침됨 / 제안한 세부 고통은 미검증.**
## 3. 부족한 점과 다음 검증
1. 목표 고객 1개를 선택하고, 최근 4주 회의 횟수와 회의 후 정리 시간을 기록한다.
2. 10~15개 팀에 최근 실제 회의 1건을 기준으로 ‘결정·근거·담당자’를 찾는 데 걸린 시간과 누락 여부를 묻는다.
3. FigJam/Miro/Teams를 쓰는 팀과 쓰지 않는 팀을 분리해 현재 대안을 확인한다.
4. 반복 기준을 사전에 정한다: 예를 들어 주 1회 이상 발생하고, 팀당 15분 이상 재정리하거나 결정 누락이 관찰될 때만 문제를 반복적이라고 판정한다.
5. 인터뷰에서 금전·보안·도입권한을 확인하기 전에는 수익 가설을 주장하지 않는다.
